# 安卓登录恢复与页面交互修复（1.2.0）

范围：App 内的登录保持和页面交互；不更换后端框架、不改变模型请求或生成超时。

## 登录机制

首次正常输入用户名密码，成功后只保留现有服务器 JWT 到 App 私有 WebView 的站点存储。
密码不会写入偏好、文件、APK 或 localStorage，成功后清空输入框。
后续打开只调用一次 `/api/v1/auth/me` 验证已保存的令牌，再加载该账户的页面和历史。
不依据本地用户名或角色缓存直接登录；角色来自服务器响应或已验证 JWT。
这里实现的是“记住有效登录”，不是永久保存账户密码，也不延长服务器签发的令牌有效期。

主动退出清除 JWT。返回首页/关闭 App 不退出账户。服务器确认无效才忘记令牌；
断网、15 秒登录验证超时、5xx 或错误 JSON 不会清除令牌，不会展示未验证私密页面。
15 秒仅约束轻量登录/验证请求，模型和流式生成没有新增超时。
普通浏览器继续要求手动登录。User-Agent 标记仅用于交互策略，不作为任何权限依据。

## 本轮定位与修复

- 启动强制删除 JWT：安卓版改为先验证保存的登录状态。
- 聊天首页返回触发退出：安卓版替换登录历史条目，返回首页关闭 App；兼容旧历史条目。
- 弹层/抽屉返回直接退出：先关闭帮助、重命名、文档、导出、技能及侧边抽屉。
- 知识库重复打开产生重复历史：同一个知识库历史条目不重复入栈。
- 旧账户/旧智能体的文档与统计延迟覆盖新页面：添加账户、智能体及请求版本校验。
- 退出后残留知识库内容/弹层：清空文档列表、统计和打开的弹层状态。
- 文件选择器返回期间页面或账户变化：原生再次验证登录生命周期和智能体，拒绝过期回调。
- 下载通道可被非本站 iframe 的伪造消息接替：每次页面使用随机 nonce，只接受相应原生通道；
  页面切换取消旧传输，并支持重新绑定缓存页面。
- 重复点登录多发请求、带空格密码被错误修剪：阻止同时重复提交，保留原始密码。

## 验证

87 项 Node 回归通过，包括账户/聊天隔离、模型选择、移动布局、登录恢复、
退出、失效、断网、超时、竞态、返回、重复打开知识库、延迟统计和文件传输。
真实 HTTPS 服务的网页登录与 Chromium 手机页面验证：首次登录一次，关闭页面再打开
无需密码；503 后保留登录并在恢复网络后重新打开自动恢复；退出后再次打开显示登录页。
实际 Chromium MessageChannel 验证分块二进制完整性及即时撤销的 Blob 导出。
这些检查拦截所有聊天模型请求，且除登录外的生产写请求均被模拟，未消耗模型额度。
APK 复用旧签名并提高 versionCode，可覆盖安装；只申请 Internet 权限。
未连接安卓真机，系统文件选择器、OEM 手势返回和真实软键盘仍需要手机验证。

## 部署

先在服务器更新以下三个文件，再覆盖安装 1.2.0 APK：

1. `app/static/js/app.js`
2. `app/static/index.html`
3. `app/static/sw.js`

既有手机布局资源、最新郑老师二维码保持不变。无须更新 `.env`、安装依赖或迁移数据库。
不备份或操作任何用户数据。首次升级完成后可能需要登录一次，此后有效期内自动恢复。
